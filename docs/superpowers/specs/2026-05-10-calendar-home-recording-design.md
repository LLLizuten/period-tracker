# 日历首页新增记录优化设计

## 背景

当前应用已经具备首页、日历页和手写日期新增记录能力，但新增记录需要用户手动输入 `YYYY-MM-DD` 日期，移动端体验成本较高。本次优化把首页信息和日历能力合并到一个页面，让用户直接在日历上选择日期，并用底部主开关标记经期开始和结束。

## 目标

- 首页和日历合并为一个日历优先页面。
- 新增记录不再要求用户手写日期。
- 用户通过“选中日期 + 主开关”标记经期开始和结束。
- 标记结束后自动保存完整经期记录。
- 保留已有记录的查看、编辑、删除能力。

## 非目标

- 不新增流量、痛经、心情、好习惯等健康指标。
- 不重构数据库结构。
- 不引入复杂的多步骤向导。
- 不改变预测算法。

## 页面结构

合并后的首页采用从上到下的信息层级：

1. 顶部摘要：展示今日日期、今日状态、最近一次经期记录、预计下一次开始日期。
2. 月历区域：展示当前月份，支持上个月、下个月、回到今天。
3. 日期详情面板：展示选中日期的状态，并承载新增记录主开关。

原日历页不再作为独立主功能入口，避免用户在首页和日历之间来回切换。

## 新增记录交互

### 初始状态

当选中日期不属于已有经期记录，且当前没有待完成的开始日期时，底部详情面板显示主开关：

- 文案：`大姨妈开始`
- 开关状态：关闭

用户打开开关后，应用记录：

- `pendingStartDate = selectedDate`

此时不写入数据库，因为还没有结束日期。

### 选择结束日期

当存在 `pendingStartDate` 后，用户继续在日历中选择另一个日期。底部详情面板的主开关自动切换为：

- 文案：`大姨妈结束`
- 开关状态：关闭

用户打开该开关后，应用自动保存记录：

- `startDate = min(pendingStartDate, selectedDate)`
- `endDate = max(pendingStartDate, selectedDate)`

保存成功后清空 `pendingStartDate`，刷新记录列表，并继续停留在日历首页。

### 取消开始标记

如果用户已经打开“大姨妈开始”，但还没有设置结束日期，可以通过关闭当前开始开关取消待完成选择。取消后：

- 清空 `pendingStartDate`
- 底部主开关回到 `大姨妈开始`

### 已有记录日期

如果选中的日期属于已有经期记录，底部详情面板优先展示已有记录：

- 记录范围
- 编辑按钮
- 删除按钮

此时不展示新增记录主开关，避免对已有记录产生歧义。

## 数据流

- 页面聚焦时初始化数据库并读取 `PeriodRecord[]`。
- 页面根据 `records` 计算今日状态、最近记录和预测日期。
- 日历日期点击只更新 `selectedDate`。
- “开始”开关只更新本地 `pendingStartDate`。
- “结束”开关调用现有 `createPeriodRecord` 自动保存。
- 保存或删除后重新读取记录，保证界面与数据库一致。

## 错误处理

- 数据加载失败：沿用现有 `Alert.alert("加载失败", message)`。
- 自动保存失败：展示 `Alert.alert("保存失败", message)`，保留 `pendingStartDate`，方便用户重试。
- 删除失败：沿用现有删除失败提示。

## 测试

- 单元测试补充新增的日期范围排序工具或状态派生逻辑。
- 类型检查保证页面合并后路由、组件 props 和日期类型正确。
- 手动验证 Expo 页面：
  - 选中开始日期后底部文案切换正确。
  - 选中结束日期并打开开关后自动保存。
  - 结束日期早于开始日期时仍保存为正确区间。
  - 已有记录日期展示编辑和删除，不展示新增开关。
  - 首页摘要和日历标记在保存后刷新。

## 原则应用

- KISS：用一个本地 `pendingStartDate` 表达未完成新增流程，不引入向导或复杂状态机。
- YAGNI：不实现参考应用里的额外健康指标。
- DRY：复用现有数据库方法、预测工具和日历工具。
- SOLID：新增交互状态只服务日历首页，数据库读写仍由 `periodRecords` 模块负责。
