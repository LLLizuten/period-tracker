# 日历首页 UI 重设计方案

## 背景

当前版本已经具备完整的核心交互闭环：

- 用户在首页日历中选择日期。
- 用户把选中日期设为开始日期。
- 用户继续在日历中选择另一天，并设为结束日期。
- 系统自动保存完整经期记录。
- 用户点击已记录日期后，可以直接查看、编辑和删除。

这套交互路径本身是成立的，满足“仅靠日历完成记录与查看”的核心诉求。

当前主要问题不在交互模型，而在 UI 表达：

- 首页更像功能原型页，不像成熟健康产品。
- 顶部摘要、日历和底部操作区层级不清。
- 主按钮使用冷蓝色，与整体暖色调不协调。
- 月历状态表达偏硬，情绪不够温和。
- 底部说明面板教程感较强，缺少产品感。

本次设计仅重做 UI，不调整核心记录逻辑，不新增独立记录页。

## 目标

- 保留现有“日历即记录器”的交互模型。
- 让首页更符合“简洁、安心、温和、可信赖”的健康产品气质。
- 强化首页对今天状态、周期信息和下一次经期预测的表达。
- 让月历成为页面主舞台，并降低记录流程的理解成本。
- 让底部操作区更像原生卡片，而不是步骤说明面板。

## 非目标

- 不改数据库结构。
- 不改开始/结束两步式记录逻辑。
- 不新增独立“记录开始/结束”的页面。
- 不在本次设计中引入症状记录和趋势页实现。
- 不调整预测算法。

## 设计原则

### 1. 日历优先

首页仍然以月历为主场。用户进入页面后，首先看到的是当前状态，其次看到的是可直接操作的月历。

### 2. 简洁克制 + 温和可信

整体风格不走高饱和甜美路线，也不走冷硬医疗路线。视觉表达保持柔和、克制、安静。

### 3. 交互不变，理解更轻

用户流程不需要重新学习，但界面要让用户更自然地理解“当前选中了什么”和“下一步该做什么”。

### 4. 一个状态只给一个主动作

底部操作卡在每个状态下只保留一个明确主按钮，避免同时出现多个竞争焦点。

## 首页信息架构

首页采用三段式结构：

1. 顶部主状态区
2. 中部月历区
3. 底部操作卡

### 1. 顶部主状态区

顶部不再使用三个权重相同的摘要卡片，而是改成一个主状态区，承载今天最重要的信息。

包含内容：

- 今天是否处于经期内
- 距离下一次预计开始还有多少天
- 最近一次记录
- 下一次预计开始日期

推荐表达方式：

- 主标题：今天不在经期内 / 今天处于经期中
- 副信息：距离下一次预计开始还有 6 天
- 辅助信息卡 1：最近记录
- 辅助信息卡 2：预计开始

设计要求：

- 顶部主状态区使用柔和暖粉渐变或浅色块作为背景。
- 辅助信息以轻量子卡片嵌入主状态区，不再散落成三个独立模块。
- 增加一句低干扰的预测说明，例如“预测基于历史记录，仅供参考”。

### 2. 中部月历区

月历是首页绝对主视觉和主交互区。

包含内容：

- 当前月份
- 上月 / 下月切换
- 回到今天
- 月历日期网格
- 日期状态表达

设计要求：

- 月份标题清晰居中。
- “回今天”弱于切月操作，可使用胶囊按钮或文字按钮。
- 月历容器使用大圆角和低对比边框，减少工具感。
- 日期状态优先依靠底色、描边和单一主色区分，不使用过多强调色。

### 3. 底部操作卡

底部区域不再表现为“步骤教程”，而改为稳定的操作卡。

它负责承载：

- 当前选中日期的信息
- 当前状态说明
- 唯一主操作
- 次级操作

底部卡片应保持统一骨架，只根据状态切换标题、说明和按钮。

## 核心状态设计

### 状态 A：默认待开始状态

触发条件：

- 当前选中日期不属于已有记录
- 当前没有待确认的开始日期

界面表现：

- 标题：将这一天设为开始日期
- 辅助说明：简短说明后续还需要选择结束日期
- 主按钮：设为开始日期

设计要求：

- 只显示一个主按钮。
- 不再展示“第一步”字样，减少教程感。

### 状态 B：待确认结束状态

触发条件：

- 用户已经设定开始日期
- 当前正在等待选择并确认结束日期

界面表现：

- 标题：将这一天设为结束日期
- 区间说明：显示当前已选区间
- 主按钮：设为结束日期
- 次按钮：重新选开始日期

设计要求：

- 已选区间需要明确展示，例如“5月12日 - 5月16日”。
- 如果结束日期早于开始日期，界面不额外解释排序规则，只在文案中简洁说明系统会自动整理区间。

### 状态 C：查看已记录状态

触发条件：

- 当前选中日期属于已保存记录

界面表现：

- 标题：这一天属于已记录经期
- 内容：展示经期起止范围
- 次级操作：编辑、删除

设计要求：

- 不展示新增记录按钮，避免歧义。
- 删除按钮始终弱于编辑按钮，避免误触。
- 删除使用偏危险色，但避免与主色过近。

## 月历状态视觉规则

月历中统一使用四种核心状态：

### 1. 普通日期

- 白色或接近白色背景
- 低对比边框
- 深灰数字

### 2. 当前选中日期

- 使用主色实心填充
- 白色数字
- 保证它是所有状态中最强的视觉焦点

### 3. 已记录经期日期

- 使用浅粉色底
- 数字颜色略深于背景
- 不额外叠加强描边

### 4. 待确认开始日期

- 不引入第二种主强调色
- 使用主色描边 + 主色文字
- 与“当前选中日期”的实心状态形成明确区分

设计约束：

- 当前选中态优先级最高。
- 已记录态负责表达历史信息，不抢主焦点。
- 待确认开始态只表达“起点被记住了”，不应比当前选中更抢眼。

## 色彩方向

整体色彩采用“简洁克制 + 温和可信”的平衡方案。

### 主色

推荐使用“豆沙玫瑰”作为主操作色和主选中色。

主色用途：

- 主按钮背景
- 当前选中日期
- 待确认开始日期描边

选择原因：

- 比冷蓝色更符合经期产品语义。
- 与暖粉、暖白页面背景协调。
- 不会像高饱和红那样产生警告感。

### 辅助色

- 背景：暖白、浅奶油白、极浅粉灰
- 卡片：白色或带轻微暖调白色
- 已记录经期：浅粉底
- 危险操作：低饱和莓红或偏深玫瑰红

色彩限制：

- 不再使用当前冷蓝作为主按钮色。
- 不引入青绿等额外强调色参与主流程状态表达。
- 删除色与主色保持清晰区分，但不使用过于刺眼的纯红。

## 排版与组件规则

### 排版

- 标题层级清晰，首页主状态信息为最大字号。
- 月历标题为次级标题。
- 辅助说明使用较浅文字色，长度控制在一到两行。
- 底部操作卡内的说明文案不超过两句。

### 留白

- 模块之间保持明显垂直间距。
- 卡片内边距大于当前版本，提升空气感。
- 不再通过频繁边框强化模块，而是通过留白和浅底色分层。

### 圆角与边框

- 大卡片建议使用更大的圆角。
- 边框保持低对比，仅用于弱分隔。
- 主状态区、月历区、底部操作卡的圆角风格保持一致。

## 文案策略

文案从“步骤解释”改为“结果导向”。

建议使用：

- 将这一天设为开始日期
- 将这一天设为结束日期
- 这一天属于已记录经期
- 距离下一次预计开始还有 6 天

避免使用：

- 第一步
- 第二步
- 当前流程
- 过长的排序、规则解释

文案目标：

- 让用户知道当前状态
- 让用户知道下一步动作
- 避免产品像教程页面

## 页面效果预期

完成本次 UI 重设计后，首页应具备以下感受：

- 第一眼能看懂今天的状态
- 月历是最强视觉中心
- 用户不需要跳转页面即可完成记录
- 操作区简洁直接，不像原型说明面板
- 视觉更温和、更统一、更有健康产品可信赖感

## 原则应用

### KISS

不改变已被验证可用的交互路径，只优化表达方式，避免因为追求新颖而增加额外复杂度。

### YAGNI

本次只处理首页 UI 层级、色彩与状态表达，不提前扩展趋势、症状或新记录模型。

### DRY

统一首页状态表达和按钮风格，不再让不同状态使用分裂的视觉语法。

### SOLID

把“交互逻辑”和“视觉表达”清晰分离：逻辑继续保持原有职责，UI 只负责提高可理解性和产品质感。
